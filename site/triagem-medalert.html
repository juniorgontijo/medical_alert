Triagem de bugs

21 bugs encontrados por teste manual + revisão de código, organizados como uma ficha de triagem: por gravidade clínica e pela ordem em que aparecem no uso real do sistema — cadastro → login → pacientes → enfermagem → alertas → médico.

📖 Glossário rápido — termos técnicos usados abaixo (clique pra abrir)

Console do navegador (DevTools): um painel escondido do navegador, pra quem desenvolve o site. Abre com a tecla F12 (ou botão direito → "Inspecionar" → aba "Console"). Dá pra colar um comandinho ali e ele executa na hora, como se fosse o próprio site fazendo aquilo.

fetch(...): o comando que se cola no Console pra fazer o navegador chamar uma rota da API diretamente (ex.: "dar alta num paciente"), sem precisar clicar em nenhum botão da tela. É só copiar e colar exatamente como está escrito no passo a passo de cada bug.

JSON: o formato de texto que a API devolve como resposta, tipo {"ok":true}. É só um jeito de organizar informação em pares "nome: valor", dá pra ler direto.

Timestamp (ex.: 1790081356243): a forma que o sistema guarda "quando algo aconteceu" — é a quantidade de milissegundos (1/1000 de segundo) contados desde 1º de janeiro de 1970. Não precisa entender o número em si, só saber que quanto menor, mais antigo é o registro.

Hash (de senha): uma senha "embaralhada" de um jeito que não dá pra desembaralhar de volta. Um sistema correto nunca guarda a senha exata, só esse embaralhado — e compara embaralhando de novo na hora do login.

IDOR: sigla em inglês pra "referência direta insegura a objeto" — na prática, significa que o sistema deixa você acessar o dado de outra pessoa só trocando um número/ID na URL ou na requisição, sem checar se você tem permissão pra aquilo.

Cookie de sessão: um "crachá" que o navegador guarda depois do login, provando quem você é nas próximas requisições. Reaproveitado automaticamente se você abrir uma nova aba no mesmo navegador — por isso vários passos pedem pra abrir "uma nova aba", sem precisar logar de novo.

Caixa-preta / Caixa-cinza / Caixa-branca (etiqueta em cada card, ao lado da camada): indica como o bug foi encontrado. Caixa-preta = só testando pela tela/API, sem acesso "por dentro" do sistema. Caixa-cinza = precisou de acesso parcial por dentro (consultar o banco, olhar a resposta crua da API no Console) mas sem ler a lógica do código. Caixa-branca = só foi possível achar (ou confirmar a causa) lendo o código-fonte — nenhum teste de tela revelaria isso sozinho.

Categoria (a etiqueta roxa/verde em cada card): o tipo de problema, não como foi achado. Segurança = alguém consegue fazer algo que não deveria (ver/alterar dado de outro, burlar login). Funcional = uma regra do sistema não funciona como deveria (cálculo errado, validação faltando). Integridade de dados = informação fica inconsistente ou é perdida/sobrescrita sem querer. Usabilidade (UX) = falta clareza ou proteção pro usuário (sem confirmação, contador errado). Visual = a tela não reflete corretamente o que está acontecendo por baixo dos panos.

Observações adicionais (não classificadas como bug isolado)

  • Todo novo paciente autocadastrado é sempre vinculado ao primeiro enfermeiro e ao primeiro médico cadastrados no banco (sem nenhum critério de distribuição) — regra de atribuição ingênua, não um erro de execução.
  • Cadastro de paciente não coleta idade nem leito — ficam vazios até alguém editar diretamente no banco; não há tela para isso.

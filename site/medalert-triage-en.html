📖 Quick glossary — technical terms used below (click to open)

Browser console (DevTools): a hidden browser panel meant for web developers. Opens with the F12 key (or right-click → "Inspect" → "Console" tab). You can paste a small command in there and it runs instantly, as if the site itself were doing it.

fetch(...): the command pasted into the Console to make the browser call an API route directly (e.g., "discharge a patient"), without clicking any button on screen. Just copy and paste it exactly as written in each bug's steps.

JSON: the text format the API returns as a response, like {"ok":true}. It's just a way of organizing information as "name: value" pairs — readable as-is.

Timestamp (e.g., 1790081356243): how the system stores "when something happened" — it's the number of milliseconds (1/1000 of a second) counted since January 1st, 1970. No need to understand the number itself, just know that smaller means older.

Hash (of a password): a password "scrambled" in a way that can't be unscrambled back. A correct system never stores the exact password, only this scrambled version — and compares by scrambling again at login time.

IDOR: short for "Insecure Direct Object Reference" — in practice, it means the system lets you access someone else's data just by swapping a number/ID in the URL or request, with no check on whether you're allowed to.

Session cookie: a "badge" the browser keeps after login, proving who you are on the following requests. It's automatically reused if you open a new tab in the same browser — that's why several steps say to open "a new tab" instead of logging in again.

Black-box / Gray-box / White-box (the tag on each card, next to the layer): indicates how the bug was found. Black-box = found purely through the screen/API, with no "inside" access to the system. Gray-box = needed partial inside access (querying the database, looking at the raw API response in the Console) but without reading the code's logic. White-box = could only be found (or confirmed) by reading the source code — no amount of testing through the screen alone would reveal it.

Category (the purple/green tag on each card): the type of problem, not how it was found. Security = someone can do something they shouldn't (view/change someone else's data, bypass login). Functional = a system rule doesn't work the way it should (wrong calculation, missing validation). Data Integrity = information becomes inconsistent, or is lost/overwritten unintentionally. Usability (UX) = missing clarity or protection for the user (no confirmation, wrong counter). Visual = the screen doesn't correctly reflect what's actually happening underneath.
